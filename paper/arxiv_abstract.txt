Retrieval providers increasingly serve knowledge to third-party agents through the Model Context Protocol (MCP): the server returns chunks tagged with source URLs, and an agent the provider does not control writes the answer. Whether that answer still cites its sources is unmeasured. We introduce Citation Survival Rate (CSR): of the gold sources an agent actually retrieved, the share cited on a claim the source supports, checked by entailment and against the logged tool-call trace. On 127 hand-verified questions over the FastAPI documentation, served by a self-hosted mirror of a commercial MCP retrieval contract, single-shot RAG and a LangGraph agent cite equally well (CSR 0.618 and 0.614, gpt-4o-mini), while an OpenAI Agents SDK agent with the same model and prompt scores 0.323. Most of that gap is format: the SDK agent ignores the requested [url] format in 51 of 127 answers, citing with Markdown links instead (single-shot: 0). A pre-registered ablation traces this to the model API the SDK calls by default; Chat Completions instead of the Responses API cuts wrong-format answers from 41 to 9. Over three runs per setup the drift recurs (46-53 answers), and a smaller real loss remains under both an NLI scorer and a gpt-4o judge (-0.12 and -0.09 CSR), absent at temperature 0. Returning a short source ID with each chunk and mapping IDs back to URLs after generation cuts wrong-format answers to 4-5 per run and closes the gap to single-shot. CSR agrees with blind human judgement on 25-27 of 30 units. We also report two failures of our own evaluation: a format-strict parser that made format drift look like a 50% citation loss, and a guardrail that looked precise to the model that built it but was 30% precise under blind human audit. Code, data, traces and labels are released.
